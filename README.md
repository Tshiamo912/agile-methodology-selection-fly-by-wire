# Agile Methodology Selection Report
### Fly-by-Wire Arduino System for Emergency Aircraft Fin Control

## 📌 Project Overview

This project involved evaluating and selecting the most suitable Agile methodology for the development of a scaled fly-by-wire aircraft control prototype using an Arduino IoT platform.

The system combines hardware and software components, including a 3D-printed aircraft model, sensors, servo motors, control algorithms, and an IoT dashboard. Due to the technical complexity and integration requirements of the project, the team evaluated different Agile approaches to determine which methodology would best support development, testing, collaboration, and risk management.

## 🎯 Project Objectives

The report focused on:

- Evaluating Agile methodologies suitable for a hardware-software integration project
- Comparing Scrum, Kanban, and Extreme Programming (XP)
- Evaluating the methodologies against project-specific requirements
- Applying SQuaRE-based software quality characteristics
- Assessing Agile tools and technologies
- Identifying suitable project metrics for progress tracking
- Considering project risks and adaptability
- Selecting and justifying the most appropriate Agile methodology

## 🔍 Methodologies Evaluated

### Scrum
A structured Agile framework based on time-boxed Sprints, defined roles, regular reviews, and continuous improvement.

### Kanban
A visual workflow methodology focused on continuous delivery, work-in-progress limits, and improving workflow efficiency.

### Extreme Programming (XP)
An Agile methodology that places strong emphasis on software engineering practices such as Test-Driven Development, continuous integration, refactoring, and pair programming.

## 🏆 Methodology Selected: Scrum

After comparing the three methodologies, **Scrum was selected as the most suitable approach** for the project.

Scrum was chosen because its structured framework provides:

- Clearly defined roles and responsibilities
- Time-boxed development Sprints
- Structured planning and prioritisation
- Regular Sprint Reviews and Retrospectives
- Better coordination between hardware and software development
- Early identification of integration problems
- Progress tracking through metrics such as velocity and burndown charts

The report concluded that Scrum provides the best balance between structure, iterative development, progress tracking, collaboration, and risk management for the project.

## 🧪 Quality Criteria

The methodologies were evaluated using project-specific quality considerations based on the SQuaRE quality model, including:

- **Reliability**
- **Performance Efficiency**
- **Maintainability**
- **Functional Suitability**

These criteria were used to assess how effectively each methodology could support the development of a reliable and functional embedded system.

## 🛠️ Agile Tools

The report also evaluated Agile project management tools, including:

- **Jira**
- **Trello**

Jira was recommended because of its advanced issue tracking, reporting capabilities, and support for Agile metrics such as velocity and burndown charts.

## 📊 Agile Metrics

The following metrics were selected to monitor project progress:

- **Velocity** – Tracks the number of technical tasks completed during each Sprint.
- **Burndown Charts** – Provides a visual representation of the remaining work.
- **Cycle Time** – Measures the time taken for a task to move from development through successful testing and calibration.

These metrics support data-driven decision-making and help identify potential delays or technical issues early.

## ⚠️ Risk & Adaptability

Key project risks considered included:

- Hardware delays or faulty components
- Difficulty estimating embedded-system tasks
- Hardware-software integration issues
- Increased documentation requirements
- Team coordination challenges

Scrum's Sprint Reviews, backlog prioritisation, incremental development, and Retrospectives were identified as mechanisms for responding to these challenges.

## 💡 Key Takeaway

This project strengthened my understanding of **Agile project management, methodology selection, software quality, risk management, and project progress tracking** within a technology-focused environment.

It also demonstrated how project management methodologies can be adapted to projects involving both physical hardware and software components.
